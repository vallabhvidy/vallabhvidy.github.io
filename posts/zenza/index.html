Zenza: Distributed Code Benchmarking Platform

2026-08-20

Running untrusted user code at scale is one of the trickiest problems in backend infrastructure. You need strict isolation, predictable resource allocation, low latency, and horizontal scalability when hundreds of jobs arrive concurrently.

I built Zenza to solve this: an asynchronous distributed benchmarking and execution platform designed to evaluate code solutions securely under heavy traffic bursts.

Architecture Overview

The platform separates request ingestion from actual execution:

[Client Web UI]
       │
       ▼ (HTTP / NDJSON Stream)
[FastAPI Gateway] ──(Enqueue Job)──► [Redis Task Queue]
                                           │
                                     (Worker Pool)
                                           ▼
                                 [Docker / Podman Sandbox]
                                 ├── Cgroups (Memory, CPU limit)
                                 ├── Dropped Linux Capabilities
                                 └── Read-only Root Filesystem

Sandbox Security & Isolation

Arbitrary user code cannot simply run on the host. Zenza leverages Docker and Podman to enforce defense-in-depth:

  • Resource Quotas: Enforced via Linux cgroups (e.g. --cpus="1.0" --memory="128m" --pids-limit=64) preventing fork-bombs and memory exhaustion.
  • Network Isolation: Disabling network egress (--network none) to prevent data exfiltration or external port probing.
  • Syscall & Capability Filtering: Stripping unnecessary capabilities (dropping CAP_NET_RAW, CAP_SYS_ADMIN) and mounting root partitions as read-only.

Realtime NDJSON Streaming (<50ms)

Instead of waiting for compilation, execution, and comparison passes to finish before returning an HTTP response, Zenza streams status frames back over NDJSON (Newline Delimited JSON). The frontend receives instantaneous feedback as compilation succeeds, execution begins, and individual test cases pass or fail.
